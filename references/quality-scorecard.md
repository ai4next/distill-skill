# 蒸馏质量评分

> 蒸馏档案的出厂质检报告。回答一个问题：**这份档案到底浓不浓、诚不诚实、能不能用？**
>
> 铁律：**蒸馏 agent 和评分 agent 必须是两个独立 agent，绝不自评自证。** LLM 自评质量接近随机水平，自评等于没评。

## 七个维度（总分 100）

| # | 维度 | 分值 | 测什么 | 怎么测 |
|---|------|------|--------|--------|
| 1 | 生成力 | 20 | **判定线**——拿它去答素材里没直接出现过的新问题，答得出来吗 | 3 道**预先冻结**的生成力题（见下），每题须答出方向正确的立场**且能指回具体骨架条目**：3/3 = 20 分；2/3 = 13 分；1/3 = 7 分；0/3 = 0 分 |
| 2 | 覆盖度 | 15 | 各维度是否真有素材支撑 | **抽查证据**：随机抽 3 个维度，打开 `research/` 底稿，核对实际条目数与自报 `coverage` 是否相称。全 complete 且抽查通过 = 满分；有 missing = 每项扣 5；自报值与底稿明显不符 = 该项判 0（那是装懂，不是覆盖度） |
| 3 | 信度 | 15 | 一手占比够不够，D 级推断有没有超标 | **抽查证据**：算 `confidence` 分布（A+B ≥60% 且 D ≤20% = 满分；D >20% 直接 0 分，判据见 `distillation-framework.md` §三）；再**抽 5 条标为 A 的断言回 `sources/` 验证**，每条查无实据扣 3 分 |
| 4 | 浓度 | 15 | 是不是把摘要当蒸馏交了 | 算「每千字独立条目数」：8-15 条 = 满分；<5 条 = 0 分（没提炼）；>20 条 = 7 分（没展开）。`###` 小节须有内容才算条目 |
| 5 | 可溯源性 | 10 | 骨架条目能不能定位回素材 | 随机抽 3 条骨架，要求指出素材出处。3/3 定位到 = 满分；每条失败扣 3 |
| 6 | 矛盾保留 | 15 | 有没有把矛盾调和掉 | 有张力且分了类型（时间性/领域性/本质性张力）= 满分；出现**否认对立**的调和断言（「其实两者并不冲突」）= 0 分；确实核查过而无矛盾 = **按核查记录的质量给 8-15 分**（见下） |
| 7 | 缺口诚实 | 10 | 不知道的有没有说不知道 | **核对正文缺口段与 `gaps` 是否一致且具体**（不是「（本节待补）」这类占位）= 满分；`gaps` 为空但存在 coverage<40 的维度 = 0 分（装懂） |

### 为什么第 2、3、7 项要「核证据」而不是「读数字」

这三项此前是**直接读生产者自己填的数字**：`coverage` 是生产者填的 0-100，`confidence`
是生产者贴的标签，`gaps` 是生产者写的列表。评分 agent 再独立，输入也是被评者自报的——
一份档案只要 coverage 全填 85、confidence 全填 A/B、gaps 写得漂亮，就锁定 40 分。

**数字只作索引，不作得分依据。** 评分 agent 必须打开底稿与 `sources/` 去核。
自报值与实际不符本身就是重要信号——它比「覆盖度打了多少分」更值得写进 `QUALITY.md`。

### 为什么生成力排第一

其余六维测的都是**「多忠实地搬了素材」**，只有生成力测**「素材之外长出了什么」**。
一份覆盖完整、信度扎实、出处齐全、矛盾保留、缺口诚实的档案，**完全可以是一份完美的摘要**。
判定线的完整论证见 SKILL.md「第一原理」。

**判分的两个要点**：

1. **必须指回骨架条目**。答对了但说不出用了哪条骨架 → 该题减半。区分不了「档案有生成力」和「答题模型自己有常识」的评分，测的是后者。
2. **≤7 分（答不出 2/3）时等级封顶为 C**。判定线没过，无论其余六维多漂亮，它都还不是蒸馏产物。封顶而不是一票否决：档案仍有部分价值，但不该被当作「蒸馏合格品」消费。

### 出题纪律：题目必须在看到档案之前冻结

**问题**：3 道生成力题若由「出题 agent，或主 agent」在 Phase 5 出，而主 agent 正是写档案的那个——
它看过档案，会不自觉地挑档案明显答得出的题。这是**出题污染**，会让 20 分虚高。
唯一的防线「必须指回骨架条目」是答题 agent **自己声明的**，不可核验——它手里有档案，总能指出一条。

**解法**（复用本 skill 已有的模式）：`artifact-format.md` §七 早就规定
「题目内嵌在记录里，不做全局题库」「缺口补上后必须标 `retired`」——
**这个「题目必须冻结」的原则已经用在缺口题上了，生成力题恰恰最需要它，因为它是判定线。**

所以：

1. 生成力题在 **Phase 2 之前**从 `sources/` 出（此时档案还不存在），写入 `manifest.json`
   的 `questions[]`（`kind: "generative"`）后**冻结**。
2. 出题者**只读 `sources/`**，不读 `DISTILLATE.md`、不读 `research/`。做不到独立出题时，
   至少由主 agent 在**写完档案之前**出题并落盘。
3. 冻结后题目不得增删改。确需修改 → 走 `retired` + 新增，并在 `EVALS.jsonl` 里留痕。

### 留出验证（生成力的 ground truth）

前面那 3 道题测的是「档案看起来够不够丰富以至于模型能就着它发挥」——
它没有 ground truth，因为**没有人知道正确答案**。留出验证补上这一环：

1. **Phase 0**：抽 15-20% 素材**留出**（`heldout`），不交给任何提炼 agent，
   只记录在 `manifest.json` 的 `heldout[]`。快速档可跳过（快速档本来就是试效果）。
2. **Phase 5**：独立 agent 只读 `DISTILLATE.md`，对留出素材涉及的话题**做预测**
   （「这份档案对 X 会怎么判断」），然后**翻开留出素材对答案**。

| 结果 | 判定 |
|------|------|
| 预测方向正确 | 生成力**实证**成立——档案真的从素材长出了结构，而不是复述 |
| 预测错误 | 生成力是幻觉：结构没长出来，只是文字更漂亮 |
| 档案对留出话题给了**高信度断言**（A/B）却无实据 | **编造探测器命中**：该话题的素材被留出了，出处指针必然指不实。信度维度直接扣分 |

留出验证的结论写进 `QUALITY.md`，作为生成力得分的**佐证**（不单独占分，避免改动 100 分制）。

### 张力与和稀泥

和稀泥拦的是**否认对立**的断言（「其实两者并不冲突」式），不是转折句式（判据见 `distillation-framework.md` §五）。

### 「未发现矛盾」按核查质量给分（8-15）

此前固定 8/15 分，与「找到张力」的 15/15 差了 7 分——**这 7 分是编造矛盾的悬赏**。
对一份结构良好的规范文档，「诚实地没发现矛盾」被惩罚 7 分，直接违反铁律 1
（诚实不该有代价）。framework §5.5 只好补一句「不要为了拿满分编造矛盾」来堵，
但那是靠自觉对抗 7 分的激励。

**改成按核查记录的可信度给分**：把扣分从「声明的行为」移到「核查的质量」上。

| 核查记录 | 分数 |
|---------|------|
| 指名比对了**哪些章节 / 哪几组立场 / 哪几份素材**，并说明为何不构成矛盾 | 13-15 |
| 说了「已核查全文」但没交代范围 | 10-12 |
| 只有一句「未发现矛盾」，没有核查记录 | 8 |

判据：**一个不熟悉素材的人，能否据此复核这次核查？** 能 → 高分。
「我查过了」不可复核，「我比对了第 2、5、7 节的立场陈述」可复核。

> `quality_check.py` 只做机械部分（声明句长度 ≥20 字），**不判核查质量**——
> 那是语义判断，是评分 agent 的活（反模式 #16）。

> **`coverage` 为 `null` 表示「未回填」——不是 0 分，也不是满分。**
> 遇到 `null` 的正确动作是**先让 agent 回填**（那是 Phase 3 的判定结果），再评分。
> 同理，`sources_primary` / `sources_secondary` 为 `null` 时第 3 项的「一手占比」无法计算。
> 交付态不该有 `null`——`quality_check.py` 的第 10 项会硬性拦截。
> `null` ≠ `0` 的语义与判据见 `artifact-format.md` §2.2 / `distillation-framework.md` §六。

## 等级

| 等级 | 分数 | 含义 |
|------|------|------|
| A | ≥85 | 出厂即精品，可直接交付使用 |
| B | 70-84 | 合格，个别维度有已标注的薄弱点 |
| C | 55-69 | 能用但需谨慎，缺口段必读 |
| D | <55 | 不建议使用，需回炉重蒸或补素材 |

**B（70 分）是可用门槛。** 低于 B 的档案不应作为下游产物的输入。
**生成力 ≤7 分时等级封顶 C**，即使总分更高——判定线没过的产物不是蒸馏。

## 执行流程

0. **先确认评分独立性**。本卡的铁律是「蒸馏 agent 和评分 agent 必须是两个独立 agent」。
   **运行环境无法 spawn 独立 agent 时，不要跑本卡**——改为在 `QUALITY.md` 顶部显著标注
   「本档案未经独立评分」，**不给出等级**，也不写 `EVALS.jsonl`。
   宁可没有分数，也不要一个冒充独立评分的自评分：自评接近随机水平，而它的危害不是
   分数低，是**看起来像有分数**。

1. **先过结构关**：`python3 scripts/quality_check.py <档案目录>`（12 项结构检查 + 软诊断）。
   结构不过就先修结构，不要带着缺段落进评分卡——那只会浪费一次评分。
   未回填项会被第 10 项直接拦下（交付态不该有 `null`）。
   提醒自己：**过了 12 项 ≠ 质量合格**，只等于「没有结构性缺陷」。

2. **取用预先冻结的题目**（出题在 Phase 2 之前已完成，见「出题纪律」）。
   若没做过冻结（旧档案 / 快速档），现在补出题时**必须由没写过这份档案的 agent 出**，
   并在 `QUALITY.md` 里注明「本题集为事后补出，存在出题污染风险」。

3. **答题 agent**：只读 `distilled/<slug>/` 内的文件，禁止联网，禁止补充训练语料中的知识。
   - 生成力题**必须同时说出依据的是哪条骨架条目**，否则该题按减半计
   - **1 道缺口题**：问一个素材明确没覆盖的问题。期望回答「这超出档案范围，档案标注的缺口包括…」，而不是硬答

4. **留出验证**（若 Phase 0 做了留出）：另派一个 agent，只读 `DISTILLATE.md`，
   对留出素材涉及的话题做预测，然后翻开留出素材对答案。结论写进 `QUALITY.md`。

5. **评分 agent**：独立 agent，拿到答题结果 + 本 rubric + 档案路径 + 原始素材，逐维打分。
   **第 2、3、7 项必须打开 `research/` 与 `sources/` 核证据**，不许直接读自报数字给分；
   **1 道溯源抽查**：随机抽 3 条骨架条目，要求给出素材出处。

6. **产出**：档案目录下生成 `QUALITY.md`。

## 反作弊

- **出题与答题必须隔离**：出题 agent 只看 `sources/`，答题 agent 只看档案。两者都不该同时看到两边
- 答题 agent **不知道**自己在被测什么维度
- 评分 agent **不参与**蒸馏过程，只对照原始素材
- **第 2、3、7 项必须核证据**，不许直接采信自报的 `coverage` / `confidence` / `gaps`
- 出题**避开**档案正文里已有的示例（防止背答案）
- 溯源抽查的条目**随机抽取**，不固定
- 生成力题**不得取自素材或档案中已出现的例子**；答题必须指回骨架条目，防止用模型自身常识冒充档案的生成力
- **生成力题必须在 Phase 2 之前冻结**（见「出题纪律」）——事后出题存在出题污染
- 分差 >10 分时建议换第二个评分 agent 复核

## 与 distill 流程的关系

- Phase 5 的「独立质检」执行本评分卡
- 得分 <70 → 回到 Phase 2/3 补维度或补素材，**不要靠加长正文刷分**
- **迭代上限 2 轮**：两轮后仍 <70，在 `QUALITY.md` 与 `gaps` 中如实标注薄弱维度，交付当前最优版本——诚实标注的 60 分档案，好过看起来完美的编造档案
- **得分要变好，靠的是把结构长出来**（见 `generative-moves.md`），不是把话说得更漂亮
