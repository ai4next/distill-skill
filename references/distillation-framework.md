# 蒸馏方法论

> 从原始素材到高浓度认知档案的核心方法论。本文件定义全套术语，其余 reference 文件共用。

## 一、蒸馏不是摘要

| | 摘要 | 蒸馏 |
|---|------|------|
| 目标 | 变短 | 变浓 |
| 保留 | 主要意思 | 结构、信度、矛盾、缺口 |
| 丢失 | 细节 | 水分 |
| 产物 | 一段话 | 可运行的认知骨架 |
| 判断标准 | 读起来概括得全不全 | 拿它去推断新问题，推得对不对 |

**判定线**：把蒸馏产物拿去回答一个素材里没直接出现过、但相关的新问题。摘要答不了，蒸馏能答——能答才是蒸馏。

**反模式**：把素材按顺序「每段缩一句」拼起来。那是压缩，不是蒸馏。蒸馏是**重组**：打散原始叙述顺序，按认知结构重新组织。

---

## 二、去水三问

每一条候选信息，过三问决定去留与权重：

| # | 问题 | 判定 |
|---|------|------|
| 1 | **删掉它，结论会变吗？** | 会变 → 留为核心骨架<br>不变 → 降级为背景/例证 |
| 2 | **它在素材里出现过几次？** | ≥3 次 → 升级为「真信念/真主张」，权重最高<br>1-2 次 → 常规条目 |
| 3 | **它是主张，还是例子？** | 主张 → 进骨架<br>例子 → 挂在对应主张下当证据（例子不单独成条） |

**关键**：重复次数是最强的去水信号。一个人在 40 万字里反复回到同一个点，那才是他的骨架；只说过一次的漂亮话，是修辞不是认知。

## 三、信度四级

**每条进入档案的信息都必须带信度标记**，无标记的断言视为不合格。

| 等级 | 名称 | 定义 | 权重 |
|------|------|------|------|
| **A** | 一手直引 | 素材原文直接支持，可定位到具体位置 | 最高 |
| **B** | 一手转述 | 素材中他人转述、但指向明确的本人言行 | 高 |
| **C** | 二手分析 | 他人的解读、评论、总结 | 中 |
| **D** | 推断 | 蒸馏者基于模式的推测，**素材中无直接支持** | 最低，须显式标注 |

规则：
- **D 级不得超过档案条目的 20%**。超过说明素材不足，应降档或标注缺口，而不是靠推断填满。
- **D 级必须显式写「（推断）」**，不允许伪装成 A/B 级。
- 信度分布写入 `DISTILLATE.md` frontmatter 的 `confidence` 字段。

## 四、三重验证

用于判断一个论点够不够格进「核心骨架」。改造自人物蒸馏，通用化后适用于所有 schema：

### 验证 1：跨域复现
同一框架出现在**至少 2 个不同领域/话题/章节**。

> 例：某人在产品决策、团队管理、个人时间分配三处都在用「可逆性」判断 → 跨 3 域复现。

### 验证 2：生成力
用这个框架可以**推断出素材里没写过的立场**。

> 检验方式：拿它去回答一个素材未覆盖的新问题。推得出且推得像 → 有生成力。

### 验证 3：排他性
**不是所有聪明人都会这样想**——它体现了这份素材的独特视角。

> 反面例：「要重视用户」「要长期主义」——正确但无排他性，所有公司都这么说。这类不进骨架。

**判级**：
- 三重全过 → **核心骨架**（最高权重）
- 过 1-2 重 → **次级条目**
- 0 重 → 丢弃，或降为背景

## 五、矛盾处理

**矛盾是信息，不是 Bug。** 遇到矛盾，保留并分类，绝不调和。

| 类型 | 表现 | 处理 |
|------|------|------|
| **时间性矛盾** | 早期说 A，后期说 B | 记录演化轨迹，标注「早期/近期」，以近期为主但保留演化 |
| **领域性矛盾** | 在工作场景主张 X，在个人场景主张 Y | 分领域记录，不强求统一——这恰是深度的来源 |
| **本质性张力** | 价值观之间的内在冲突（既追求自由又强调纪律） | 明确列为「核心张力」，通常是整份档案最有价值的部分 |

**❌ 错误处理**（任一条出现即质检不合格）：
- 选一边忽略另一边
- 编一个「其实两者是统一的」式调和解释
- 假装矛盾不存在
- 把矛盾写成「虽然…但是…」的和稀泥句式

## 六、缺口标注

**不知道就说不知道。** 每份档案必须显式列出信息缺口。

缺口来源：
- 某维度素材稀少（`manifest.json` 中 `coverage < 40`）
- 关键问题素材中从未涉及
- 素材主体**刻意回避**某话题（这本身是重要信息，要如实标注为「主动不公开」而非「信息缺失」）

规则：
- `gaps` 字段**必须存在**，允许为空列表（空 = 确实无已知缺口）
- 缺口须写进 `DISTILLATE.md` 正文的「信息缺口」段
- summon 消费时，`gaps` 必须映射进人格的「诚实边界」段

## 七、蒸馏比与浓度

```
蒸馏比 = 素材总字数 : 档案字数
```

| 档位 | 典型蒸馏比 | 适用 |
|------|-----------|------|
| 快速 | 100:1 以上 | 素材量小、只要骨架 |
| 标准 | 30:1 ~ 60:1 | 大多数场景 |
| 深度 | 10:1 ~ 25:1 | 精品档案，保留大量证据链 |

**蒸馏比不是越低越好。** 比值过低（<10:1）通常意味着没蒸馏，只是重排了原文。真正的浓度信号是：

> **每千字档案里，有多少条能通过三重验证的独立条目。**

**浓度区间**（每千字档案的独立条目数）：

| 区间 | 判定 |
|------|------|
| < 5 | 水太多，继续去水 |
| 5-8 | 可接受，偏稀 |
| **8-15** | **健康** |
| 15-20 | 可接受，偏密 |
| > 20 | 没展开，读者理解不了 |

`scripts/quality_check.py` 以 **5-20 为通过带**（<5 或 >20 判 FAIL）；上限只在正文 ≥800 字时才判定，短文档天然密度偏高。

## 八、维度划分原则

维度决定 `research/` 的文件划分与并行 agent 的数量。

| schema | 维度 |
|--------|------|
| `person` | 著作 / 对话 / 表达 / 他者 / 决策 / 时间线（6 维，见 `schema-person.md`） |
| `topic` | 领域共识 / 流派分歧 / 关键概念 / 经典案例 / 争议前沿 / 演进脉络（6 维，见 `schema-topic.md`） |
| `document` | 论点树 / 证据链 / 术语表 / 隐含假设 / 内部矛盾 / 信息缺口（6 维，见 `schema-document.md`） |
| `custom` | 用户自定义，2-8 个，编号 `01`-`08` |

维度划分的三条要求：
1. **互斥**：一个素材片段应主要归属一个维度，避免重复计数
2. **穷尽**：所有素材都能找到归属；找不到 → 说明维度设计有漏
3. **可并行**：维度之间无依赖，能被不同 agent 独立处理

## 九、信息不足时的处理

| 情况 | 处理 |
|------|------|
| 某维度素材很少 | `status: partial`，标注「信息不足，此维度为推测」，D 级标记 |
| 只有二手信息 | 降信度至 C，标注「据…报道」 |
| 信息互相矛盾且无法判断 | 并列呈现，保留矛盾，让读者自行判断 |
| 素材主体刻意回避 | 如实标注「对此话题保持沉默」，**不要替他生成立场** |
| 素材总量 <10 条 | Phase 0.5 就告知用户质量受限；骨架条目减至 3-5 条；加厚缺口段 |
| 完全无素材 | **停止**。不要凭训练语料生成档案——那是在编造 |

## 十、质量自检清单

### 骨架
- [ ] 每条核心骨架都过了三重验证？
- [ ] 骨架条目数在 3-7 条之间？（少于 3 = 没提炼；多于 10 = 没取舍）
- [ ] 每条都标了信度等级？
- [ ] 拿骨架能推断素材未覆盖的新问题？（生成力实测）

### 浓度
- [ ] 每千字 8-15 条独立条目？
- [ ] 删掉了纯例子、纯修辞、纯重复？
- [ ] 不是原文顺序的重排？

### 诚实
- [ ] 矛盾保留了，且分了类型？
- [ ] 缺口写全了？
- [ ] D 级占比 <20%？
- [ ] 没有无来源的断言？

### 可用
- [ ] 换个不熟悉素材的人读，能抓住骨架？
- [ ] 档案能被直接消费（喂给 summon 或人读）？
- [ ] 删掉标题后，还能认出这是哪份素材的认知？
