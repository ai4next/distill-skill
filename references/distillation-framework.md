# 蒸馏方法论

> 从原始素材到高浓度认知档案的核心方法论。本文件定义全套术语，其余 reference 文件共用。
> 每条规则为什么存在，见 SKILL.md 的「第一原理」——**规则是推论，不是清单**。

## 一、蒸馏不是摘要

判定线（权威定义在 SKILL.md）：

> **拿产物去回答一个素材里没直接出现过、但相关的新问题。摘要答不了，蒸馏能答。**

| | 摘要 | 蒸馏 |
|---|------|------|
| 目标 | 变短 | 变浓 |
| 保留 | 主要意思 | 结构、信度、矛盾、缺口 |
| 丢失 | 细节 | 水分 |
| 产物 | 一段话 | 可运行的认知骨架 |
| 判断标准 | 读起来概括得全不全 | 拿它去推断新问题，推得对不对 |

**反模式**：把素材按顺序「每段缩一句」拼起来。那是压缩，不是蒸馏。蒸馏是**重组**：
打散原始叙述顺序，按认知结构重新组织。

---

## 二、去水三问

每一条候选信息，过三问决定去留与权重：

| # | 问题 | 判定 |
|---|------|------|
| 1 | **删掉它，结论会变吗？** | 会变 → 留为核心骨架<br>不变 → 降级为背景/例证 |
| 2 | **它在素材里出现过几次？** | ≥3 次 → 升级为「真信念/真主张」，权重最高<br>1-2 次 → 常规条目 |
| 3 | **它是主张，还是例子？** | 主张 → 进骨架<br>例子 → 挂在对应主张下当证据（例子不单独成条） |

**关键**：重复次数是最强的去水信号。一个人在 40 万字里反复回到同一个点，那才是他的骨架；
只说过一次的漂亮话，是修辞不是认知。

## 三、信度四级 = 证据距离轴

信度**不是质量评分**，是**这条信息距离原文有多远**——中间隔了几层转述：

```
原文 ────A────▶ 转述 ────B────▶ 解读 ────C────▶ 推断 ────D
素材直引         指向明确的        他人的          蒸馏者基于
可定位到具体位置  本人言行          评论、总结       模式的推测
```

| 等级 | 名称 | 定义 | 权重 |
|------|------|------|------|
| **A** | 一手直引 | 素材原文直接支持，可定位到具体位置 | 最高 |
| **B** | 一手转述 | 素材中他人转述、但指向明确的本人言行 | 高 |
| **C** | 二手分析 | 他人的解读、评论、总结 | 中 |
| **D** | 推断 | 蒸馏者基于模式的推测，**素材中无直接支持** | 最低，须显式标注 |

规则：

- **每条进入档案的信息都必须带信度标记**，无标记的断言视为不合格。
- **D 级必须显式写「（推断）」**，不允许伪装成 A/B 级。
- **D 级不得超过档案条目的 20%**。
- 信度分布写入 `DISTILLATE.md` frontmatter 的 `confidence` 字段。

### 为什么是 20%

这个数字不是拍脑袋的。**D 级条目不来自素材**——它们是蒸馏者的推断。

一份档案里 D 级超过两成，意味着它已经不再是「这份素材的认知档案」，而开始变成
「蒸馏者对这个话题的看法」。前者可溯源、可复用、可被反驳；后者换个蒸馏者就完全不同
——**它蒸馏的是蒸馏者自己**。

20% 是「档案的主体仍然属于素材」的临界点。超过它不是格式错误，是**方向错了**：
正确动作是标注缺口，而不是靠推断填满。

### 出处与信度必须同行

光有信度不够——**「A 级」这个断言本身也需要被核验**。所以推荐把两者写在行尾同一对括号里：

```markdown
- 用可逆性判断替代预测，只在错了也不致命时下注（A · sources/notes/note1.md）
```

写法与机械检查规则见 `artifact-format.md` §2.3。

## 四、三重验证

用于判断一个论点够不够格进「核心骨架」。改造自人物蒸馏，通用化后适用于所有 schema：

### 验证 1：跨域复现

同一框架出现在**至少 2 个不同领域/话题/章节**。

> 例：某人在产品决策、团队管理、个人时间分配三处都在用「可逆性」判断 → 跨 3 域复现。

**它防的是**：把一次偶然的表达误当成稳定认知。

### 验证 2：生成力

用这个框架可以**推断出素材里没写过的立场**。

> 检验方式：拿它去回答一个素材未覆盖的新问题。推得出且推得像 → 有生成力。

**它防的是**：把复述误当成骨架。这是判定线本身，权重最高。

### 验证 3：排他性

**不是所有聪明人都会这样想**——它体现了这份素材的独特视角。

> 反面例：「要重视用户」「要长期主义」——正确但无排他性，所有公司都这么说。这类不进骨架。

**它防的是**：把常识误当成这份素材的认知。

**判级**：

- 三重全过 → **核心骨架**（最高权重）
- 过 1-2 重 → **次级条目**
- 0 重 → 丢弃，或降为背景

## 五、矛盾处理：补全语境后，冲突还在不在？

**矛盾是信息，不是 Bug。** 但「什么才算矛盾」必须先说清楚——否则「保留矛盾」会退化成
「把任何两处不一致都并列摆着」，而「不调和」会退化成「禁止做任何综合」。

### 5.1 判据：语境可消解性

> **把省略的语境补回来，这个冲突还在不在？**

- **补全之后消失了** → 冲突的根源是**语境被省略了**，不是主张真的对立 → **低阶张力**
- **补全之后依然对立** → 根源在价值观排序本身 → **本质性张力**

| 类型 | 表现 | 性质 | 处理 |
|------|------|------|------|
| **时间性张力** | 早期说 A，后期说 B | **命题随认知演化而改变** | 记录演化轨迹，标注「早期/近期」与**触发事件**；以近期为主但保留演化 |
| **领域性张力** | 工作场景主张 X，个人场景主张 Y | **命题的条件不同** | 分领域记录，并写明**条件差异是什么**（权重不同？约束不同？） |
| **本质性张力** | 同一命题下同时主张 A 与非 A（既追求自由又强调纪律） | **真矛盾** | 明确列为「核心张力」，通常是整份档案最有价值的部分 |

### 5.2 两类张力各揭示什么

这不是分类癖——两类张力**提供的信息种类不同**：

| | 低阶张力（时间性 / 领域性） | 本质性张力 |
|---|---|---|
| 揭示 | **条件的边界**：这个主张在什么条件下成立、什么时候不成立 | **价值的排序**：冲突时优先牺牲哪个、保住哪个 |
| 用法 | 知道边界，才知道产物什么时候**不该被采信** | 知道排序，才能**推断未覆盖场景**该怎么选 |
| 与生成力的关系 | 划定生成力的**适用范围** | 生成力的**主产地** |

所以两类都要记录——**低阶张力是生成力的边界条件，不是次等的信息**。

前两类之所以看起来像冲突，是因为命题的**尺度**（时间）或**条件**（领域）被省略了。
把省略的部分补回来，冲突就消失了——这不是调和，是**补全语境**。
第三类才是真矛盾：补全语境之后它依然对立。**这一类绝不允许被抹平。**

### 5.3 和稀泥的判据：信息量净减少，不是句式

**「虽然…但是」本身不是和稀泥**，它是描述张力的合法形式。把句式当罪证，会硬性
判掉一条标注齐全的时间性张力，逼作者删掉真实矛盾——检查在惩罚正确输出。

> **判据：把改写后的句子还原，还能不能取出被调和前的两条主张？**

| | 写法 | 信息量 | 判定 |
|---|------|--------|------|
| ✅ **综合** | 他在工作中主张放权、在家庭中事无巨细，**因为他对「可控性」的权重随场景不同** | 两条主张都在，**还多出了归因** → 增加 | 合法，是深度的来源 |
| ❌ **和稀泥** | 虽然他在工作中主张放权，但他在家庭中事无巨细，**其实两者并不冲突** | 差异被「并不冲突」抹掉，取不回原来的张力 | 非法，质检不合格 |

区别不在句式，在**信息量是增是减**。抹平的对立面不是「并列摆着」，是「正确地综合」。

### 5.4 错误处理（任一条出现即质检不合格）

- 选一边忽略另一边
- **否认对立**：编一个「其实两者是统一的」「并不冲突」「殊途同归」式的调和解释
- 假装矛盾不存在
- 把本质性张力降格成「时间性/领域性」来回避它（**用分类代替消解**）
- 反过来，把时间性/领域性张力硬说成「核心张力」（**用消解代替分类**）

> `quality_check.py` 的 `HARMONY_RE` 只拦**否认对立**的断言，
> 不拦转折句式。转折句式在**缺类型标注**时进软诊断提示复核——缺标注的转折，
> 多半是把对立揉平了；有类型标注则完全合法。

### 5.5 「确实没有矛盾」怎么处理

矛盾段**不允许留空**——沉默无法区分「真的没有」与「没看」（见 §六）。
确实核查过而无矛盾时，显式写出声明并交代核查范围（如「已比对全文各章节的立场陈述，
未发现前后不一致」），`quality_check.py` 认这种写法，评分卡该维记 8/15 分（非满分）。

> 反过来说：**不要为了拿满这一维而编造矛盾。** 编出来的矛盾违反铁律 1，
> 比诚实声明「未发现」更糟。声明无矛盾时会进软诊断提示复核，这是刻意的——
> 它该被看见，但不该被拦截。

## 六、缺口标注：区分「没看」与「没有」

> **整份档案的诚实性，建立在一个区分上：「素材里没有」和「我没去看」是两回事。**

这个区分有**五次现身**。它们看起来是五条不相干的规则，其实是同一件事：

| 现身 | 没看（未判定） | 没有（已判定） |
|------|--------------|--------------|
| 字段值 | `null` = 还没判 | `0` = 判定为没有 |
| 维度覆盖 | `coverage: null` 未回填 | `coverage: 0` 确实没覆盖 |
| 矛盾 | 矛盾段留空 → **判 FAIL** | 显式声明「未发现矛盾」+ 核查范围 |
| 推断 | 未标注 → 读者以为来自素材 | 显式标「（推断）」= D 级 |
| 沉默 | 当缺口去补 → 会**编造立场** | 标注「主动不公开」= 沉默本身是信息 |

**沉默永远不能替代声明。** 留空、不写、默认值——这些都让读者无法区分「查过了没有」
和「压根没查」。前者是诚实的边界，后者是失职。档案的价值取决于读者能否信任它的边界。

### 缺口来源

- 某维度素材稀少（`manifest.json` 中 `coverage < 40`；`coverage` 为 `null` 表示**未回填**，须先回填再判）
- 关键问题素材中从未涉及
- 素材主体**刻意回避**某话题（这本身是重要信息，要如实标注为「主动不公开」而非「信息缺失」）

### 规则

- `gaps` 字段**必须存在**，允许为空列表（空 = 确实无已知缺口）
- 缺口须写进 `DISTILLATE.md` 正文的「信息缺口」段
- 被下游消费时，`gaps` 必须映射为产物中的「诚实边界 / 局限说明」段

## 七、蒸馏比与浓度

```
蒸馏比 = 素材总字数 : 档案字数
```

| 档位 | 典型蒸馏比 | 适用 |
|------|-----------|------|
| 快速 | 100:1 以上 | 素材量小、只要骨架 |
| 标准 | 30:1 ~ 60:1 | 大多数场景 |
| 深度 | 10:1 ~ 25:1 | 精品档案，保留大量证据链 |

**蒸馏比不是越低越好。** 比值过低（<10:1）通常意味着没蒸馏，只是重排了原文。
真正的浓度信号是：

> **每千字档案里，有多少条能通过三重验证的独立条目。**

**浓度区间**（每千字档案的独立条目数）：

| 区间 | 判定 |
|------|------|
| < 5 | 水太多，继续去水 |
| 5-8 | 可接受，偏稀 |
| **8-15** | **健康** |
| 15-20 | 可接受，偏密 |
| > 20 | 没展开，读者理解不了 |

`scripts/quality_check.py` 以 **5-20 为通过带**（<5 或 >20 判 FAIL）；上限只在正文 ≥800 字时才判定，短文档天然密度偏高。

**「独立条目」的机械口径**：核心骨架条数 + **有内容的** `###` 小节数（小节正文 ≥20 字才算）。
空 `###` 标题是免费的分子，不计入——否则「加 7 个空小节」就能把一份零提炼的档案刷成
「每千字 10.7 条」的健康浓度。

### 七之前的一条：过滤器不生产生成力

去水三问（删）、信度四级（降级）、三重验证（筛）、张力分类（不许抹平）、缺口标注（不许补）
——§二~§七 全是**过滤器**，每一个动作都在防。判定线要的「素材之外长出的结构」不在这里，
在 `generative-moves.md` 的五个生成算子：张力外推 / 结构迁移 / 边界外推 / 反问题 / 组合。

**关键纪律**：算子产出的是**结构**（价值排序、适用边界、条件差异），不是结论。
把推出来的结论写进档案会撞上三道墙——D 级占比超标、守卫 3 禁止新增断言、浓度被稀释。

## 八、素材、信息源与维度

### 8.1 维度划分原则

维度决定 `research/` 的文件划分与并行 agent 的数量。

| schema | 维度 |
|--------|------|
| `person` | 著作 / 对话 / 表达 / 他者 / 决策 / 时间线（6 维，见 `schema-person.md`） |
| `topic` | 领域共识 / 流派分歧 / 关键概念 / 经典案例 / 争议前沿 / 演进脉络（6 维，见 `schema-topic.md`） |
| `document` | 论点树 / 证据链 / 术语表 / 隐含假设 / 内部矛盾 / 信息缺口（6 维，见 `schema-document.md`） |
| `custom` | 用户自定义，2-8 个，编号 `01`-`08` |

维度划分的三条要求：

1. **互斥**：一个素材片段应主要归属一个维度，避免重复计数
2. **穷尽**：所有素材都能找到归属；找不到 → 说明维度设计有漏
3. **可并行**：维度之间无依赖，能被不同 agent 独立处理

### 8.2 素材类型 → 处理方式与覆盖维度

| 素材类型 | 处理方式 | 主要覆盖维度 |
|---------|---------|------------|
| 书籍 PDF | 直接阅读提取核心论点 | 著作、表达 |
| 演讲/访谈 transcript | 分析问答模式与即兴反应 | 对话、表达 |
| 视频字幕 SRT/VTT | 同 transcript | 对话、表达 |
| 博客/newsletter 导出 | 提取系统性观点 | 著作、表达 |
| 社交媒体导出 | 分析碎片表达模式 | 表达 |
| 会议纪要 | 提取决策逻辑与分歧 | 决策、隐含假设 |
| 聊天记录 | 提取立场、术语、冲突 | 表达、内部矛盾 |
| 代码库 | 架构决策 + 调用点 + 测试 | 论点树、证据链 |
| 用户整理的笔记 | 作为二手来源交叉参考 | 视内容 |

### 8.3 信息源权重

| 来源类型 | 揭示什么 | 权重 |
|---------|---------|------|
| 用户提供的一手素材 | 完整原文，未经二手过滤 | **最高+** |
| 本人著作 / 原始文档 | 系统性思考 | 最高 |
| 长对话 / 访谈 | 即兴思维过程 | 最高 |
| 实际决策记录 | 真实行为 vs 声称 | 最高 |
| 社交媒体 | 表达风格、即时反应 | 中等 |
| 他人评价 | 外部视角、盲点 | 中等 |
| 二手转述 | 参考但需验证（C 级） | 低 |

**本地语料的质量优势**：用户手上的一手素材（完整书籍、长访谈原文、内部文档）通常比
网络二手转述质量高得多，在信度上直接进 A/B 级。

**信息源黑名单（永远排除）**：知乎、微信公众号、百度百科/百度知道。中文渠道只接受
权威媒体（36氪、极客公园、晚点LatePost、财新、第一财经、虎嗅、少数派、机器之心等）；
人物访谈类可用小宇宙/喜马拉雅原始音频、B站原始视频（非搬运号）。

## 九、信息不足时的处理

| 情况 | 处理 |
|------|------|
| 某维度素材很少 | `status: partial`，标注「信息不足，此维度为推测」，D 级标记 |
| 只有二手信息 | 降信度至 C，标注「据…报道」 |
| 信息互相矛盾且无法判断 | 并列呈现，保留矛盾，让读者自行判断 |
| 素材主体刻意回避 | 如实标注「对此话题保持沉默」，**不要替他生成立场** |
| 素材总量 <10 条 | Phase 0.5 就告知用户质量受限；骨架条目减至 3-5 条；加厚缺口段 |
| 完全无素材 | **停止**。不要凭训练语料生成档案——那是在编造 |

## 十、质量自检清单

**骨架**——每条核心骨架都过了三重验证？条目数在 3-10 条之间（少于 3 = 没提炼；多于 10 = 没取舍）？
每条都标了信度等级？拿骨架能推断素材未覆盖的新问题？
