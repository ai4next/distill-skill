# 对抗精炼（Adversarial Refine）

> 评分卡告诉你档案得多少分，对抗精炼告诉你**分数丢在哪一行**。它不重新打分，只交一份可机械执行的补丁候选清单。位置：Phase 5 独立质检**之后**、Phase 6 交付**之前**，两个攻击者并行开火、互不可见。

## 一、两个攻击者

| | 攻击者 | 猎物 |
|---|---|---|
| A | **信度攻击者** | 无来源的断言；伪装成 A/B 级的 D 级条目；被「虽然…但是…」和稀泥掉的矛盾 |
| B | **浓度攻击者** | 灌水段落；没展开的骨架条目；可合并的重复条目；把例子当主张单独成条的条目 |

两者**必须并行 spawn、互不可见**。串行会让 B 读到 A 的结论，双方收敛到同一批问题上，覆盖面直接减半。攻击者**只读**档案，不写——发现的问题一律走补丁清单，由人（或主 agent）裁定后落地。攻击者自己动手改档案，等于把「发现」和「处置」合并，无法审计。

## 二、四个守卫（本文件的核心）

四个守卫不是流程装饰，每一个都堵一个具体的失败模式。缺任何一个，对抗精炼都会退化成「一个 agent 骂另一个 agent」。

### 守卫 1：必须交补丁

每条攻击**必须**同时交齐三样：

| 要件 | 内容 |
|------|------|
| **before / after 文本** | 原句 + 改写后的句子（删则 after 为空并标「删除」） |
| **命名的评分卡维度** | 必须是六维之一：覆盖度 / 信度 / 浓度 / 可溯源性 / 矛盾保留 / 缺口诚实 |
| **被攻击行号** | `DISTILLATE.md` 的精确行号（或 `research/0X-*.md` 路径 + 行号） |

三样缺任意一样 → 该条**直接丢弃**，不进入补丁清单，只在「已丢弃」区留一行审计记录。

**为什么**：一条不带补丁的攻击是**意见**，不是发现。意见无法被验证（改哪句？改成什么？），也无法被机械应用（落到哪个维度？动哪一行？）。只有「原句 → 新句 + 维度 + 行号」这种形式，才能让裁定者不看攻击者的脸色、只看 diff 就能拍板。这是把主观不满转成可执行工单的唯一办法。

### 守卫 2：攻击者必须拿到 ground truth

攻击者的 prompt 里**必须**给到 `distilled/<slug>/sources/`（原始素材）与 `manifest.json` 的 `sources` 清单，且允许其按行号回查原文。

**为什么**：没有 ground truth，攻击者只能攻击**文风**——它会看到每条 A 级断言都只标注了「（A）」，却无从核对，于是把「我查不到出处」误判为「没有出处」，要求把整份档案的 A/B 级批量降为 C/D。这不是提纯，是**信度通缩**：一份信度扎实的档案会被攻击到满目疮痍，而真正的编造条目反而因为「看起来和别的一样」而蒙混过关。攻击者手里有原文，才分得清「无出处」和「我没去查」。

### 守卫 3：只许删改，不许新增断言

精炼只能**删**（删水、删例子、删重复）或**改**（降信度、拆条目、并条目、把调和改写为矛盾分类），**绝不允许新增任何档案里没有的断言**。

| ✅ 允许 | ❌ 禁止 |
|---|---|
| 删掉第 88 行的灌水段 | 补一句「此外他还认为…」 |
| 把伪装 A 级的第 42 行降为 D 级并标「（推断）」 | 给第 42 行补一个素材里没有的出处 |
| 把两行重复条目合并成一行 | 把某条骨架「展开得更完整」而引入新论据 |
| 把「虽然…但是…」改写为并列的领域性矛盾 | 替素材主体补一个他没表过的立场 |

**为什么**：新增内容是**在不动质量的前提下刷分**的标准手法——加两段漂亮话，浓度分母变了、覆盖度看起来更满了，但档案的认知含量一寸没长。这条守卫同时堵死反模式 #11「靠加长正文刷浓度分」：浓度看的是每千字**独立条目数**（健康区间 8-15），灌水只会稀释，不会提浓。素材没覆盖的，正确动作是写进 `gaps`，不是拿训练语料填。

### 守卫 4：不做「必须提升否则回滚」的评分闸门

本 pass 的产出是**补丁候选清单**，交给用户/主 agent 裁定，**不重新打分、不设回滚阈值**。

**为什么**：单个 LLM 的评分有 **±5-10 分噪声**——两份评分卡都写着「分差 >10 分时建议换第二个评分 agent 复核」。若设一道「精炼后必须提分否则回滚」的闸门：

- 分数抖动 +6 分时 → 闸门放行，其实什么都没修好，纯噪声被当成进步
- 真实的修补撞上 -7 分的噪声 → 闸门回滚，把唯一做对的一处改回原样

一半概率放过噪声，一半概率杀掉真修复。**质量信号从来不来自同一次评分的涨跌，而来自跑第二个独立评分 agent。** 精炼结束后要判断有没有变好，就重跑 Phase 5 评分卡（结果追加进 `EVALS.jsonl`，见 `artifact-format.md` 第七节），对照两次分维度得分——而不是让攻击者兼裁判。

## 三、Spawn prompt 模板

### A · 信度攻击者

```
你的任务：对 distilled/<slug>/DISTILLATE.md 做信度对抗审查。你是攻击者，只找问题，不修复。

你可以读：distilled/<slug>/DISTILLATE.md、research/0X-*.md、manifest.json、
以及 distilled/<slug>/sources/ 下的全部原始素材。你有原文，回查是你的义务。

只猎三类目标：
1. 无来源的断言——正文里任何一条既无信度标记、又无出处的句子
2. 伪装成 A/B 级的 D 级条目——素材中查无实据，却未标「（推断）」
3. 被和稀泥的矛盾——「虽然…但是…」式调和，把矛盾揉成了温吞共识

每条攻击必须交齐四件，缺一件则该条作废：
- before：被攻击的原句（逐字）
- after：改写后的句子（纯删除则写「删除」）
- 维度：覆盖度 / 信度 / 浓度 / 可溯源性 / 矛盾保留 / 缺口诚实 之一
- 行号：DISTILLATE.md 或 research/0X-*.md 的精确行号

铁律：
- 不许新增断言。只许删、只许改、只许降信度。
- 查不到出处 ≠ 没有出处。先回 sources/ 查，查过仍无据，才按第 2 类报。
- 不要提「整体感觉」「建议加强」这类无行号的意见——会被直接丢弃。
- 你不打分，不改档案。产出交回主 agent。
```

### B · 浓度攻击者

```
你的任务：对 distilled/<slug>/DISTILLATE.md 做浓度对抗审查。你是攻击者，只找问题，不修复。

你可以读：distilled/<slug>/DISTILLATE.md、research/0X-*.md、manifest.json。
原始素材在 distilled/<slug>/sources/，需要核对事实时可查。

只猎四类目标：
1. 灌水——不承载认知的过渡句、重复铺陈、正确的废话
2. 没展开的骨架条目——只有一句话、缺证据/生成力/局限，读者理解不了
3. 可合并条目——两条讲同一件事，占两个条目位
4. 例子冒充主张——素材里的个案被单独成条，未挂在对应主张之下

每条攻击必须交齐四件，缺一件则该条作废：
- before：被攻击的原句（逐字）
- after：合并/展开/删除后的文本
- 维度：覆盖度 / 信度 / 浓度 / 可溯源性 / 矛盾保留 / 缺口诚实 之一
- 行号：DISTILLATE.md 或 research/0X-*.md 的精确行号

铁律：
- 不许新增断言。合并条目不得引入任何一方没有的内容。
- 「展开」只许用同一条目已有的证据，不许去 sources/ 之外找补。
- 删水时只删句子，不删它承载的信息；信息有价就改写，无价才删。
- 你不打分，不改档案。产出交回主 agent。
```

## 四、补丁清单输出格式

落盘为 `distilled/<slug>/REFINE.md`。

```markdown
# 对抗精炼补丁候选清单

**档案**：DISTILLATE.md @ sha256 3a71…（version N）| 日期：YYYY-MM-DD | 轮次：1/2
**攻击者**：A 信度 / B 浓度（独立双 agent，互不可见）

| # | 攻击者 | 维度 | 行号 | 攻击理由 | before | after | 处置 |
|---|--------|------|------|---------|--------|-------|------|
| 1 | A | 信度 | 42 | 断言无出处，疑似 D 级伪装 A 级 | … | …（推断） | 采纳 |
| 2 | B | 浓度 | 88 | 与第 31 行重复，可合并 | … | … | 采纳 |
| 3 | B | 浓度 | 103 | 例子单独成条 | … | … | 驳回：该例为跨域复现证据 |

## 已丢弃（缺要件，仅留审计）
- [A] 行 77：只有理由，无 before/after → 丢弃
- [B] 行 12：未命名维度 → 丢弃

## 裁定摘要
采纳 N 条 · 驳回 M 条 · 存疑 K 条
**未改动断言数量：0**（精炼只删改，不新增）
```

**处置**三选一：`采纳` / `驳回` / `存疑`。驳回必须写理由（如「该例是三重验证的跨域证据」）——驳回理由本身是下一轮的输入。

## 五、迭代上限

**最多 2 轮**，与 Phase 5 的迭代上限一致：第 1 轮 A/B 并行开火 → 补丁清单 → 裁定落地；第 2 轮对落地后的档案重跑 A/B，**只处理新暴露的问题**，不重复攻击已驳回项；第 2 轮后无论清单多长都停手。

**为什么是 2 轮**：精炼的终点是「诚实标注的 60 分档案」，不是「看起来完美的 90 分档案」。第 3 轮开始，攻击者会开始制造**无补丁可交的攻击**（把已驳回项换个说法再报一遍），或诱导编辑者新增内容来「补完整」——两条路都直接撞上守卫 1 与守卫 3。**对抗精炼绝不演变成刷分。** 两轮后仍有问题，写进 `QUALITY.md` 的「待修复」与 `gaps`，如实交付。

## 六、质检清单

- [ ] A/B 是**并行 spawn** 的两个独立 agent？互不可见？
- [ ] 攻击者 prompt 里给了 `sources/` 与 `manifest.json` 的 `sources`（守卫 2）？
- [ ] 每条攻击都带 before/after + 命名维度 + 行号？缺要件的已进「已丢弃」区（守卫 1）？
- [ ] 全部 after 文本里，**没有一条新增断言**？（守卫 3）
- [ ] 本 pass **没有**重新打分、没有设回滚阈值（守卫 4）？
- [ ] 驳回项都写了理由？第 2 轮只处理新问题、未重报已驳回项？
- [ ] 轮次 ≤2？两轮后仍不达标的维度已写进 `QUALITY.md` 与 `gaps`？
- [ ] 要判断精炼是否有效，已另跑**第二个独立评分 agent** 并追加 `EVALS.jsonl`？
